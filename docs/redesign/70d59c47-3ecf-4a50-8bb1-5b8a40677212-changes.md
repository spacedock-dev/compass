# Session 70d59c47: creating a summary

**Path:** 5. A session that needs its summary created.

**Session:** Haiku 5.5 adding reason tokens for checks with no recorded result in `compass`
(worktree `haiku-4890`, draft PR #636). It is 8 minutes old with about 200k output tokens and 94+
entries. I pressed `Summarize` right after its turn ended. Observed on the `:4560` build of
`feature/session-redesign`.

**References:** the Session Redesign design (`Main.dc.html`) and the sample session.

Severity: **P1** breaks the flow or misleads, **P2** departs visibly from the design, **P3** polish.

## Before the summary

1. **P2 · The session's title is the issue key.** The page and the tab title show only the issue key. The
   other sessions got a descriptive title ("ProjectTabs duplicate tab and panel ids"). When the
   title is only an identifier, the page should fall back to the goal or the first prompt.
2. **P1 · The outline starts partway through an 8-minute session.** "Compass read only the newest
   part of this session's record, so the outline starts partway." Its only phase is titled `Before
   the first message of yours this outline read`. For a session started minutes ago, the outline
   misses its own first prompt. The read bound is in bytes, and a busy session passes it in
   minutes. The reader then sees no phase they recognise.
3. **P2 · Estimate and progress disagree.** Before: `More than 94 entries to read in at least 2
   parts, up to 10 minutes.` During: `Summarizing: part 1 of 3`. "At least 2" turned into 3 without
   saying so. It finished in about 30 seconds against "up to 10 minutes".
4. **P2 · The same failure listed twice.** The outline shows `Failed as the tool reported: vitest
   run --config frontend/.storybook/vitest.config.mts ... Activity` on two lines, one with a `#40.1`
   anchor and one without.
5. **P3 · "Analyze is open: the session's last turn finished."** "Open" is internal language for a
   gate. It means "you can analyze now", and with the button directly above it the sentence is not
   needed.

## While it summarizes

6. **P1 · The one-time summary notice stays above the summary for good.** "This request sends:" (a
   long paragraph, `Provider`, `Words go to`, `Turn off summaries`) opens at the top of the card on
   the first press. It is still there after the summary finishes, pushing the opening paragraph down
   about 300px. In the design, the story is the first thing in the card.
7. **P2 · The header says "summarized at 11:06" while it is still summarizing.** The card header
   showed `claude-sonnet-5-5 · summarized at 11:06` with `Summarizing: part 3 of 3` and `Cancel`
   below it.
8. **P3 · Phases arrive collapsed.** As each part lands, its phase title appears as a closed
   disclosure, with `The opening summary is written once every part has been read.` above them.
   That works, but the reader sees titles only, never a bullet, until they open each one.

## The finished summary

9. **P2 · Phases are collapsed by default.** The design shows the opening paragraph and then the
   bullets, visible. Here every phase is a closed `⌄` heading. The sample session also collapses
   them. If they stay collapsed, the phase that holds a departure should open by default.
10. **P2 · The opening paragraph speaks of "the person".** "The person asked the agent to implement
    <issue key>, so ... where the entries end." The design's opening describes what the
    agent did: "The agent rebased PR 56 onto main and cleared the conflicts. Windows CI then
    failed, ...". "The person" is the reader, so it should say "you", or leave the reader out.
11. **P1 · A caveat after almost every citation.** "(3 cited entries are earlier checks or files that
    Full activity does not list, so they cannot be opened from here.)" follows the opening paragraph
    and most bullets. It explains an internal limit (Full activity's window) at every line. Say it
    once at the foot of the card, or make the citations open.
12. **P2 · Bullets are long and mechanical.** For example: "The vitest run from the frontend folder
    reported not-recorded, as the tool reported, with the agent attributing the window errors to
    environment setup; the agent reran from the repo root." The design's bullets are one short clause
    each ("Added a failing test to `test_http_api.py` and is starting a fix.").
13. **P2 · `Said:` prefix.** One bullet reads "Said: The agent wrote a story that renders one row per
    reason." The prefix is a kind marker leaking into the text.
14. **P2 · The hidden line's label is jargon.** "1 line hidden: it said, in the summary's own voice,
    that work was done or working. Entries #40.1 to #44, and 1 more." plus `Why it was hidden ⌄`. The
    reader should be told "One line was left out because the record does not back it."
15. **P3 · `1 failure` badge on a phase.** The failure is the Storybook browser run failing in the
    agent's sandbox (an environment limit the agent reported). The badge has the same weight as a
    real test failure.
16. **P3 · Footer.** "Each line cites the entries it rests on. Compass checks that a cited entry
    exists and what kind it is, not that it supports the line." then `Delete summary`, `What is sent
    to Claude Code ⌄`, `Compass's outline of this session ⌄`. The design has no footer. The sentence
    is useful once, but `Delete summary` as the first button reads as the main action of the card.
